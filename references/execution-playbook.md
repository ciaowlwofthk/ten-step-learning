# Execution Playbook · Quantitative Metrics and Delivery Self-Check

This file is the execution layer of `SKILL.md`: step-by-step operating rules, the five perspective definitions, scoring weights, quantitative metrics and the pre-delivery self-check list. The main file handles routing and red lines; execution follows this file.

## Step-by-step operating rules

Every row below is a hard rule; the five perspectives for step 1 and the weight table for step 4 are in the two appendix tables at the end.

| Step | Operating rules |
|:--|:--|
| 0 · Topic framing and fact check | ① Define the topic and its scope (region, time, population); write the scope into the opening of the deliverable, not just the conversation; ② anything involving "current facts" must be verified online first — current rules, product lists, entry thresholds, prices, institution names, statutes; training data is necessarily stale and writing from memory produces wrong deliverables; ③ prefer official sources (exchanges / regulators / governments / vendor docs), then original reporting from authoritative media; single sources must be labeled; ④ unify the verification record into three columns — **conclusion / source / verification date** — visible in the deliverable |
| 1 · Five-perspective expert panel | Fixed five perspectives (Appendix 1). **Each must deliver three items, none optional**: **position / core evidence (3 points, numeric where possible) / exclusive hidden insight**. A hidden insight is what that perspective knows but usually does not say — counterparty view, survivorship bias, conditions under which its assumptions fail, identity positioning |
| 2 · Contradiction list | All four blocks required: **A. Viewpoint conflicts**: conflict → pro side → con side → **adjudication** (state "who is right under which conditions"; no fudging); **B. Evidence strength grading**: very strong (mathematical identity) / strong (multi-market or multi-source empirical) / weak (personal experience, screenshots); **C. Points of consensus**: 4–6 items no perspective objects to; **D. Industry blind spots**: 4–6 items almost nobody raises in the discussion (usually the most valuable) |
| 3 · Concise briefing | ① **60-second script**: one read-aloud paragraph in plain language (about 300–400 words), no jargon stacking; ② **5 key findings**: in descending credibility, one sentence each that fully explains the point; ③ **3 action recommendations**, concrete enough to state "which three things to do this week / which three iron rules to set / what not to touch for 90 days" |
| 4 · Credibility scoring | Table columns `No.｜Finding｜Credibility (0-100)｜Basis type｜Status｜What is still missing for full verification`; formula **evidence-type weight × freshness coefficient** (weights in Appendix 2); **one rubric per table**: decide the basis type first, then look up freshness — no scoring by impression; anything below 80 must be marked `to verify` with the **specific missing data** named (never just "more research needed"); the freshness coefficient follows the verification date, and anything clearly outdated drops a tier; proactively name 1–2 pseudo-propositions "worth abandoning outright" to save the user time |
| 5 · Resources and roadmap | ① **Write the selection criteria first** (e.g. authoritative rules / verifiable / available in the reader's language / practice-oriented) and state what was deliberately excluded (e.g. marketing-account interpretations, second-hand retellings); ② 5 resources covering **1 systematic textbook + 1 official rule source + 1 practitioner-oriented book + 1 free structured course + 1 hands-on tool**; ③ table columns `No.｜Resource｜Type｜Why this one｜Search identifier`; ④ **one-week roadmap** Day 1–Day 7, each day stating "goal + output", and the output must be checkable |
| 6 · Five-level learning ladder | Fixed five levels: **cognition → rules → pricing/principle → strategy → practice**. Each level has three items: **passing criteria (self-testable) / pitfalls / self-test question**. End with an "advancement map" giving the rough investment per level and naming the most common level-skipping failure |
| 7 · 20-hour sprint | ① Break into **8 modules**, total duration **exactly 20 hours**, each module with a "check output", table columns `Module｜Topic｜Duration｜Core content｜Check output`; ② separately list **5–7 hands-on mini-projects**, each stating "what to do / what you get / why this project works"; ③ at least 1 **observation-only project** — observation replaces real losses, the best value for effort |
| 8 · Quiz (interaction gate) | ① Increasing difficulty ★ → ★★★★: first 3 basic, 4–7 intermediate, 8–10 advanced; ② **4 options each**, and **every wrong option gets a diagnosis** explaining "why you would think that and where it goes wrong"; ③ **no skipping**: even after a wrong answer, explain fully before moving on; ④ end with scoring guidance: what 8–10 / 6–7 / ≤5 correct means, which level it corresponds to, and what to strengthen; ⑤ never complete this section on the user's behalf before they answer; if the user asks to skip, state the loss first |
| 9 · Feynman explanation (interaction gate) | ① Carry it with one **everyday story** (insurance, reservation coupons, bets, tickets), zero jargon or explain terms immediately; ② about 5 progressive sub-sections, each closing with a one-sentence takeaway; ③ include at least **1 hand-drawn-style diagram** (inline SVG for profit/loss, flow, or comparison); ④ end with a **retelling check**: 5–7 sentences telling the user "if you can say these, you have graduated"; ⑤ explicitly invite the user to retell, and explain how to degrade the explanation when they cannot (change the story, split smaller, return to the matching level in step 6) |
| 10 · Five-minute cheat sheet | One page, dark title bar + grid sections, must contain six sections: `core concepts｜key metrics/variables｜viewpoint→solution map｜rules/parameters｜entry thresholds｜risk red lines`. Add a "one-sentence memory" table compressing the 3–4 most important points into short sentences |

Check by group; anything unchecked means rework (23 items):

- [ ] Step 0 has the three columns "conclusion / source / verification date", sources official or first-hand
- [ ] Key evidence carries numbers or verifiable sources
- [ ] Low-scoring items name the specific missing data category
- [ ] Factual content is labeled with source and verification date
- [ ] 1–2 pseudo-propositions recommended for abandonment are named
- [ ] Every number/date has been compared against the verification table: each traces to a source; unsourced ones are deleted or marked 〔illustrative〕

**Structure and panel (3)**
- [ ] Five perspectives present, each with three items (position, 3 evidence points, hidden insight)
- [ ] Contradiction list has all four blocks (conflicts, grading, consensus, blind spots)
- [ ] Every conflict has a conditional adjudication

**Outputs and acceptance (6)**
- [ ] Resources cover five categories, with selection criteria and deliberate exclusions stated
- [ ] Every day of the one-week roadmap has a checkable output
- [ ] Every ladder level has passing criteria, pitfalls and a self-test question
- [ ] 8 modules total exactly 20 hours
- [ ] At least 1 observation-only project
- [ ] 10 questions with increasing difficulty, every wrong option diagnosed

**Explanation and risk control (4)**
- [ ] The Feynman section is jargon-free, with a diagram and 5–7 retelling criteria
- [ ] High-stakes topics carry a disclaimer
- [ ] Investment conclusions carry conditions and sample sources; no causal claims
- [ ] If an exception occurred, the user was guided per "Error handling and degradation", and degraded output is explicitly marked

**Delivery and environment (4)**
- [ ] The cheat sheet fits on one page with all six sections
- [ ] The HTML is a self-contained single file, readable on mobile
- [ ] PDF page count was verified via the maximum `/Count` or `/Type /Page`
- [ ] Temporary scripts were cleaned from the delivery directory

## Appendix 1 · The fixed five perspectives

| Perspective | Represents | Position characteristics |
|:--|:--|:--|
| Simulated practitioner | 10 years on the front line | Talks feel, position sizing, real sources of loss |
| Researcher | Theory/model camp | Talks mathematics and provable structure |

## Appendix 2 · Credibility basis-type weights

| Basis type | Weight range |
|:--|:--|
| Mathematical identity | 90–100 |
| Multi-market / multi-source empirical | 80–90 |
| Industry structural fact | 75–85 |
| Single-sample statistics | 60–75 |
| Personal experience, hearsay | 40–60 |

Formula: **credibility = basis-type weight × freshness coefficient**. The three worked examples below cover the three situations where scoring is easiest to fudge; follow them case by case — never score by impression.

### Worked scoring examples

**Example 1 · Mixed evidence takes the strongest weight**: when a finding is supported by both "multi-market empirical (weight 80–90)" and "personal experience (weight 40–60)", take **the strongest category** as the weight — do not average. Multi-market empirical evidence stands on its own, so use the 80–90 band; personal experience is only corroboration, noted in the "basis type" column, and does not drag the score down. Conversely, if the strong evidence is overturned and only personal experience remains, recompute by the personal-experience band — do not carry the old score.

**Example 2 · Freshness coefficient**: default 1.0; verified within 1 year and the source still valid = 1.0, 1–3 years = 0.9, over 3 years or the source revised/invalid = from 0.7 downward tier by tier; clearly outdated items (rules repealed, prices expired) drop to 0.6 or below. Example: multi-market empirical weight 85, but the data is 4 years old and the market structure has changed → 85 × 0.7 = 59.5 → record 60 (rounded to a multiple of 5), below 80, marked "to verify".

**Example 3 · Picking a value inside the range**: weights are ranges, not fixed values. Three criteria: ① directness of the source (first-hand official > second-hand retelling); ② sample coverage (cross-market/multi-source > single market single source); ③ reproducibility (recomputable > unverifiable). All three strong → upper bound; middling → midpoint; barely qualified → lower bound. Never exceed the range (e.g. personal experience scored 70, or a mathematical identity compressed to 80 "to be conservative").

### Fixed wording for low scores (mandatory for any "to verify" item below 80)

> This conclusion scores 〔score〕 (basis type: 〔type〕, freshness coefficient: 〔coefficient〕) and is marked "to verify" for now. It still needs 〔specific data type, e.g. "full-sample backtest after 2024" / "the official current text of the statute"〕 to reach 80+; until then, use it as "holds under 〔conditions〕, confidence 〔high/medium/low〕".

Banned empty phrases: "more research is needed", "needs observation", "evidence is insufficient". Name the missing data category and roughly where to find it. Numbers and dates get the same treatment: every number/date in the document must trace to the verification table or a source; untraceable ones are deleted or marked 〔illustrative〕 and never mixed into conclusions.
